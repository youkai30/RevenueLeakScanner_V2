2. ACTUAL FUNCTION CALL TRACE
StoreLoader.load_stores_from_file(file_path) -> Validates and returns list[StoreRecord].
worker.execute_single_store_worker(store_dict) -> Spawns Playwright via BrowserFactory.
IntegratedStoreScanner.scan_store(page, store_record):
Calls ProductDiscoveryEngine.discover_pdp_urls(page, store_record.base_url).
Iterates up to max_candidates=3 discovered URLs:
page.goto(url, wait_until="domcontentloaded", timeout=15000)
product_title = (page.title() or domain).split("|")[0].strip()
VariantMatrixScanner(page).inspect_variants()
VariantMatrixScanner(page).discover_and_select_oos_variant()
BISChecker(page).check_notify_mechanism()
CROStackDetector(page).detect_review_widget()
CROStackDetector(page).detect_cro_modules()
Mobile context check if sticky ATC absent & scrollHeight >= 1200.
Appends PDPScanResult with evaluated CommercialOpportunity objects into TransientScanContext.
CommercialImpactCalculator.build_commercial_impact_dto(scan_context, traffic):
Computes oos_ratio = total_oos / total_inspected.
Computes est_monthly_loss_usd = traffic * oos_ratio * baseline_cr * aov.
Applies mandatory -0.30 confidence penalty for fallback traffic and -0.05 for fallback AOV.
EvidenceCollector(page).capture_screenshot_bytes():
Executes page.screenshot() ONCE on whatever page is currently loaded after the scan loop finishes.
EvidenceBuilder.compile_and_save_session():
Wraps findings and png_bytes into Finding objects.
Seals SessionBundle with SHA-256 checksum and saves to storage/sessions/{domain}/{session_id}/.
PayloadCompiler + PDFDriver + TeaserDriver:
Generates audit.pdf and teaser.png.
CommercialLeadExporter.assemble_lead(bundle):
Sorts opportunities by priority: REVENUE_LEAK (1) > MISSING_STICKY_ATC (2) > MISSING_SOCIAL_PROOF (3) > MISSING_UPSELL (4).
Executes PostScanEnricher.enrich_bundle(bundle) for metadata (brand name, contact page).
Evaluates lead_class: Class A if REVENUE_LEAK or (opps >= 1 and coverage == FULL).
CommercialLeadExporter.export_leads():
Serializes CommercialLeadRecord items to leads.json and leads.csv.

CRITICAL FINDING: UNKNOWN STATE DOES NOT EXIST IN ANY ENGINE.

Product Discovery: Candidate URLs matching /products/ or containing digits are unconditionally accepted. Cloudflare walls, category pages, and editorial pages are processed as valid PDPs.
Variant Matrix: Returns (variant_name, True) if any selector element is disabled. Returns ("Default Variant", False) otherwise. No state for ambiguous/pre-selection elements.
BIS Checker: Returns (notify_detected, sold_out_detected). Returns False if selectors/text are absent. No distinction between "no BIS form" and "BIS form lazy-loaded/uninspectable".
CRO Stack Detector:
Reviews: Returns review_widget_detected = False if platform is not Yotpo, Okendo, Loox, Judge.me, Stamped.io, or Shopify PR.
Upsell: Returns upsell_detected = False if 8 selectors fail.
Sticky ATC: Returns sticky_atc_detected = False if 3 selectors fail on desktop and mobile.
5. CURRENT EVIDENCE MODEL AUDIT
Screenshot Capture Timing: Captured ONCE per store scan after all candidate PDPs (up to 3) have been navigated and evaluated (worker.py line 83).
Screenshot Representation: Represents the final page state of the last inspected URL in the scan loop.
Scope Level: Session-level screenshot shared across all findings. It is NOT finding-level.
Finding Linkage: The exact same png_bytes and bounding_boxes are assigned to every Finding in the SessionBundle. Finding 1 (PDP 1) receives the screenshot of PDP 3.
Storage: Saved on disk at storage/sessions/{domain}/{session_id}/session_{session_id}.png.
Verification: VisualVerifier asserts PNG stream integrity, dimensions (>=1024x600), and canvas non-blankness. It does not verify whether the screenshot matches the product URL or title of the finding.
Path Validity: VisualEvidence.relative_path stores https://{domain}/products/{slug}/session_{id}.png. This is a pseudo-URL and does not point to a disk file.
Claim Proovability: Current evidence cannot prove individual finding claims because screenshot evidence is decoupled from the PDP page state that produced the finding.
6. CURRENT COMMERCIAL MODEL AUDIT
Finding Definition: A PDPScanResult containing one or more CommercialOpportunity DTOs.
Opportunity Definition: A boolean evaluation inside core_scanner.py where the absence of a positive detection signal generates a sellable service angle.
Lead Definition: A CommercialLeadRecord aggregated across all findings for a single domain (1 store = 1 lead).
Confidence Computation: Hardwired constant 0.65 produced by subtracting fixed fallback penalties (1.0 - 0.30 - 0.05).
Impact Computation: Est. Monthly Loss = 50,000 traffic * OOS_Ratio * 0.02 CR * $65 AOV.
Classification Logic (Class A / B / C):
Class A — SELLABLE: Primary opportunity is REVENUE_LEAK with loss > 0, OR unique_opp_types >= 1 with coverage == FULL (3 PDPs inspected).
Class B — USABLE WITH CAUTION: coverage == PARTIAL (< 3 PDPs inspected).
Class C — NOT SELLABLE: Unused in current dataset (requires coverage < FULL and zero opportunities).
What Makes a Lead "SELLABLE" Currently: Scan completion across 3 PDP URLs resulting in at least 1 un-detected feature selector. Class A reflects scan completeness, not commercial opportunity quality.

CONTRACT-PDP-001: PDP / Page Validity Contract
PURPOSE: Prevent opportunity engines from executing on Cloudflare challenges, error pages, collection pages, or editorial pages.
INPUT GUARANTEE: A Playwright Page instance navigated to a target candidate URL.
OUTPUT GUARANTEE: A strongly-typed PAGE_STATE classification:
REAL_PRODUCT
CLOUDFLARE_BLOCKED
ACCESS_DENIED
NOT_PRODUCT (Collection, Blog, Cart, Checkout)
REDIRECTED
ERROR_PAGE
LOGIN_REQUIRED
UNKNOWN
INVARIANTS:
Opportunity engines MUST NOT execute if PAGE_STATE != REAL_PRODUCT.
UNKNOWN or CLOUDFLARE_BLOCKED state MUST immediately terminate scan for that URL with status BLOCKED / SKIPPED.
FORBIDDEN STATES:
Generating any CommercialOpportunity on a page where PAGE_STATE != REAL_PRODUCT.
Using Cloudflare interstitial titles (e.g. "Connexion en cours...") as product_name or company_name.
FAILURE BEHAVIOR: Return PAGE_STATE.BLOCKED or PAGE_STATE.NOT_PRODUCT, log diagnostic warning, discard PDP result.
DOWNSTREAM ASSUMPTIONS: Opportunity engines can safely assume the DOM represents a single, active Shopify product page.
TEST REQUIREMENTS: Test against Cloudflare 403 html, Shopify collection pages (/collections/all), blog articles (/blogs/news), 404 pages, and valid product pages.
CONTRACT-STATE-001: TRUE / FALSE / UNKNOWN State Contract
PURPOSE: Enforce a strict 3-state detection model across all primary opportunity engines.
INPUT GUARANTEE: Validated DOM context on a REAL_PRODUCT page.
OUTPUT GUARANTEE: Detection state MUST evaluate strictly to TRUE, FALSE, or UNKNOWN.
INVARIANTS:
UNKNOWN MUST NEVER generate a commercial opportunity.
Converting "selector not found" directly into "feature absent" without positive evidence of absence is strictly forbidden.
FORBIDDEN STATES:
Binary True/False flags where negative detection implies commercial problem.
FAILURE BEHAVIOR: Fallback to UNKNOWN state on any ambiguous selector match or evaluation timeout.
DOWNSTREAM ASSUMPTIONS: CommercialOpportunity generator receives explicit, verified states only.
TEST REQUIREMENTS: Assert that an unrecognised DOM layout returns UNKNOWN and yields 0 commercial opportunities.
CONTRACT-EVIDENCE-001: Finding Evidence Contract
PURPOSE: Guarantee 1:1 binding between a commercial finding and the visual screenshot of the exact page state that produced it.
INPUT GUARANTEE: Playwright Page execution context captured IMMEDIATELY after finding evaluation on that specific PDP.
OUTPUT GUARANTEE: A unique VisualEvidence object with verified PNG bytes, valid dimensions, SHA-256 hash, and readable disk path.
INVARIANTS:
Every Finding MUST have its own unique screenshot PNG captured at the time of PDP inspection.
Two findings from different PDP URLs MUST NOT share the same screenshot PNG hash.
VisualEvidence.relative_path MUST point to a valid, physically existing file on disk (storage/sessions/...).
FORBIDDEN STATES:
Reusing a single session-level screenshot across multiple PDP findings.
Storing pseudo-URLs or HTTP endpoints in relative_path.
Setting evidence.valid = True when the screenshot depicts an interstitial, blank, or error page.
FAILURE BEHAVIOR: Mark finding evidence as INSUFFICIENT, lower confidence rating, demote lead classification.
DOWNSTREAM ASSUMPTIONS: Exporters and PDF drivers can directly load and render the screenshot file from relative_path.
TEST REQUIREMENTS: Assert that 3 inspected PDPs generate 3 distinct PNG files with 3 unique SHA-256 hashes on disk.
CONTRACT-VARIANT-001: Variant Identity Contract
PURPOSE: Ensure out_of_stock = True represents a genuine unavailable product variant SKU.
INPUT GUARANTEE: DOM elements matching variant picker controls on a REAL_PRODUCT page.
OUTPUT GUARANTEE: Confirmed OOS status + human-readable variant SKU name.
INVARIANTS:
Generic disabled Add-to-Cart buttons (disabled before option selection) MUST NOT be classified as OOS variants.
Loading states, unselected option placeholders, and disabled quantity steppers MUST NOT trigger out_of_stock = True.
Raw opaque variant IDs (e.g. "7038539891054") MUST be flagged for translation or marked AMBIGUOUS.
FORBIDDEN STATES:
Classifying a pre-selection disabled CTA as an OOS variant.
Matching non-variant elements via broad class name substring matches (e.g. .slider-disabled).
FAILURE BEHAVIOR: Return VariantState.AMBIGUOUS or VariantState.UNKNOWN.
DOWNSTREAM ASSUMPTIONS: Revenue Leak engine receives only confirmed OOS variant states.
TEST REQUIREMENTS: Mock pre-selection disabled ATC button -> assert out_of_stock == False. Mock real disabled size pill -> assert out_of_stock == True.
CONTRACT-BIS-001: Back-in-Stock Contract
PURPOSE: Ensure REVENUE_LEAK opportunities are generated ONLY when OOS is confirmed AND BIS capture is proven absent.
INPUT GUARANTEE: A confirmed OOS variant page state (VariantState.OUT_OF_STOCK).
OUTPUT GUARANTEE: REVENUE_LEAK opportunity generated ONLY if all 5 conditions are satisfied:
PAGE_STATE == REAL_PRODUCT
Product variant identified & verified OOS
BIS detection executed ON THAT SPECIFIC OOS PAGE STATE
BIS notification form/button proven absent (BISState.ABSENT)
Evidence PNG captured of the OOS state
INVARIANTS:
BIS Checker MUST NOT execute on in-stock or unverified page states.
If BIS state is UNKNOWN (e.g. dynamic modal unverified), REVENUE_LEAK MUST NOT fire.
FORBIDDEN STATES:
Generating REVENUE_LEAK when out_of_stock = False.
Generating REVENUE_LEAK when BIS detection is UNKNOWN.
FAILURE BEHAVIOR: Set opportunity status to UNVERIFIED / NONE.
DOWNSTREAM ASSUMPTIONS: Financial impact calculator computes loss strictly on verified REVENUE_LEAK leads.
TEST REQUIREMENTS: Test OOS page with Klaviyo BIS modal -> 0 REVENUE_LEAK opportunities. Test OOS page without BIS -> 1 REVENUE_LEAK opportunity.
CONTRACT-REVIEW-001: Review Detection Contract
PURPOSE: Prevent false MISSING_SOCIAL_PROOF findings for stores using unlisted or enterprise review platforms.
INPUT GUARANTEE: DOM context and page script resources of a REAL_PRODUCT page.
OUTPUT GUARANTEE: ReviewState: REVIEWS_CONFIRMED_PRESENT, REVIEWS_CONFIRMED_ABSENT, or REVIEWS_UNKNOWN.
INVARIANTS:
Selector failure across hardcoded platforms MUST evaluate to REVIEWS_UNKNOWN, NOT REVIEWS_CONFIRMED_ABSENT.
MISSING_SOCIAL_PROOF MUST ONLY fire if ReviewState == REVIEWS_CONFIRMED_ABSENT (verified via multi-layer inspection: JSON-LD AggregateRating, star text regex, generic DOM class patterns).
FORBIDDEN STATES:
Generating MISSING_SOCIAL_PROOF when review state is REVIEWS_UNKNOWN.
Ignoring JSON-LD schema.org AggregateRating metadata present in the page head.
FAILURE BEHAVIOR: Set state to REVIEWS_UNKNOWN, suppress opportunity generation.
DOWNSTREAM ASSUMPTIONS: Any MISSING_SOCIAL_PROOF lead represents a verified absence of customer reviews.
TEST REQUIREMENTS: Test page with JSON-LD reviews -> REVIEWS_CONFIRMED_PRESENT. Test page with unknown review widget -> REVIEWS_UNKNOWN (0 opportunities).
CONTRACT-UPSELL-001: Upsell Detection Contract
PURPOSE: Prevent false MISSING_UPSELL findings based solely on 8 CSS selector checks.
INPUT GUARANTEE: DOM context of a REAL_PRODUCT page.
OUTPUT GUARANTEE: UpsellState: PRESENT, ABSENT, or UNKNOWN.
INVARIANTS:
Absence of 8 CSS selectors MUST evaluate to UpsellState.UNKNOWN.
MISSING_UPSELL MUST NOT be exported as a sellable commercial opportunity until behavioral cart-drawer inspection is implemented.
FORBIDDEN STATES:
Classifying a lead as Class A based solely on MISSING_UPSELL.
FAILURE BEHAVIOR: Default to UpsellState.UNKNOWN, output 0 commercial opportunities.
DOWNSTREAM ASSUMPTIONS: Lead exporter ignores MISSING_UPSELL for Class A qualification.
TEST REQUIREMENTS: Assert that selector absence returns UpsellState.UNKNOWN and generates no Class A lead.
CONTRACT-STICKY-001: Sticky ATC Contract
PURPOSE: Guarantee sticky ATC evaluation reflects the real mobile viewport purchase experience.
INPUT GUARANTEE: Mobile Playwright context (375x667, mobile UA, touch enabled) on a REAL_PRODUCT page with scrollHeight >= 1200px.
OUTPUT GUARANTEE: StickyATCState: PRESENT, ABSENT, or UNKNOWN.
INVARIANTS:
Sticky ATC evaluation MUST include behavioral scroll verification (scroll to 50% height, evaluate fixed/sticky CTA element in lower viewport fold).
Selector inspection MUST check expanded theme patterns (.js-sticky-atc, .product-sticky-bar, [data-sticky], etc.).
FORBIDDEN STATES:
Declaring sticky ATC absent on pages with scrollHeight < 1200px.
Declaring sticky ATC absent without running mobile context scroll evaluation.
FAILURE BEHAVIOR: Return StickyATCState.UNKNOWN.
DOWNSTREAM ASSUMPTIONS: MISSING_STICKY_ATC leads represent verified mobile conversion friction.
TEST REQUIREMENTS: Mobile scroll test on fixed bottom bar -> PRESENT. Mobile scroll test on un-stickied page -> ABSENT.
CONTRACT-IMPACT-001: Commercial Impact Contract
PURPOSE: Ensure financial loss estimations explicitly disclose parameter provenance.
INPUT GUARANTEE: TransientScanContext with verified OOS metrics and optional measured traffic/AOV.
OUTPUT GUARANTEE: CommercialCalculationResult with explicit ParameterSource provenance tags (PRIMARY_MEASURED, BENCHMARK_CATEGORY, FALLBACK_ASSUMED).
INVARIANTS:
Fallback traffic (50k) and fallback AOV ($65) MUST be tagged as FALLBACK_ASSUMED.
Financial loss output MUST include explicit framing text: "Benchmark Scenario Estimate".
Benchmark assumptions MUST NEVER be presented as store-specific facts.
FORBIDDEN STATES:
Labeling fallback revenue loss as "Actual Measured Store Revenue Loss".
FAILURE BEHAVIOR: Apply mandatory confidence penalties (-0.30 for fallback traffic, -0.05 for fallback AOV).
DOWNSTREAM ASSUMPTIONS: Buyer presentation UI clearly demarcates estimated vs. measured financial data.
TEST REQUIREMENTS: Verify that output DTO contains has_fallback_parameters = True and explicit benchmark footnote.
CONTRACT-CONFIDENCE-001: Confidence Contract
PURPOSE: Provide a dynamic, per-lead confidence rating reflecting true data & evidence quality.
INPUT GUARANTEE: Page validity state, engine detection certainty, evidence verification status, and financial provenance.
OUTPUT GUARANTEE: confidence_score float between 0.0 and 1.0.
INVARIANTS:
Confidence rating MUST NOT be a fixed static constant across all leads.
confidence_score MUST factor: page validity (+0.3), finding certainty (+0.3), evidence quality (+0.2), measured parameters (+0.2).
Any lead with fallback financial parameters MUST be capped at confidence_score <= 0.69.
FORBIDDEN STATES:
Returning 0.65 uniformly for all generated leads.
FAILURE BEHAVIOR: Demote confidence score to < 0.50 on unverified evidence or partial coverage.
DOWNSTREAM ASSUMPTIONS: Lead classification logic uses confidence_score as a quality gate.
TEST REQUIREMENTS: Test lead with full measured data -> confidence >= 0.85. Test lead with fallback traffic -> confidence <= 0.69.
CONTRACT-CLASSIFICATION-001: Lead Classification Contract
PURPOSE: Ensure Class A "SELLABLE" status reflects true commercial opportunity quality, not scan completion.
INPUT GUARANTEE: SessionBundle containing validated findings, evidence statuses, and commercial impact.
OUTPUT GUARANTEE: lead_class: A — SELLABLE, B — USABLE WITH CAUTION, or C — NOT SELLABLE.
INVARIANTS:
Class A REQUIRES either: (a) Verified REVENUE_LEAK finding, OR (b) Verified MISSING_STICKY_ATC with confidence_score >= 0.65 and evidence_status == VERIFIED.
Leads with only MISSING_UPSELL or UNVERIFIED findings MUST NOT be classified as Class A.
Leads with PAGE_STATE != REAL_PRODUCT or contaminated evidence MUST be classified as Class C — NOT SELLABLE.
FORBIDDEN STATES:
Assigning Class A based purely on coverage == FULL and selector absence.
FAILURE BEHAVIOR: Downgrade to Class B or Class C.
DOWNSTREAM ASSUMPTIONS: Buyers receiving Class A leads receive high-precision commercial opportunities.
TEST REQUIREMENTS: Session with only MISSING_UPSELL -> Class B. Session with Cloudflare wall -> Class C. Session with verified OOS -> Class A.
CONTRACT-DEDUP-001: Identity & Deduplication Contract
PURPOSE: Ensure store, product, and variant entities are deduplicated at the true domain identity level.
INPUT GUARANTEE: Ingested store domains and scraped PDP variant attributes.
OUTPUT GUARANTEE: Deduplicated finding matrices and financial OOS ratios.
INVARIANTS:
1 Target Domain = Exactly 1 CommercialLeadRecord.
Duplicate URLs pointing to the same product SKU MUST NOT double-count OOS variants in impact_calculator.py.
Variant identity deduplication MUST use (product_id/handle, variant_id/name) composite keys.
FORBIDDEN STATES:
Incrementing variants_oos multiple times for the same OOS variant discovered on 2 URL variants of the same product.
FAILURE BEHAVIOR: Merge duplicate variant records prior to financial calculation.
DOWNSTREAM ASSUMPTIONS: oos_frequency_pct reflects unique variant availability ratio.
TEST REQUIREMENTS: Pass 2 PDP results containing the same OOS variant ID -> verify variants_oos = 1.
CONTRACT-ENRICH-001: Enrichment Contract
PURPOSE: Guarantee enrichment status accurately reflects contact data population.
INPUT GUARANTEE: SessionBundle passed to post-scan enrichment pass.
OUTPUT GUARANTEE: enrichment_status: SUCCESS, PARTIAL, FAILED, or NOT_ATTEMPTED.
INVARIANTS:
enrichment_status = "SUCCESS" REQUIRES at least one verified direct contact method (contact_email OR contact_phone).
If only inferred contact_page is available, enrichment_status MUST be "PARTIAL".
company_name MUST be extracted from brand metadata (OG site_name, JSON-LD publisher), NOT raw product page titles.
FORBIDDEN STATES:
Setting enrichment_status = "SUCCESS" when contact_email and contact_phone are both null.
Labeling hardcoded /pages/contact URLs as contact_page_source = "DOM_LINK".
FAILURE BEHAVIOR: Set enrichment_status = "PARTIAL", record diagnostic notes.

1. PAGE STATE MACHINE (PageState)
States
DISCOVERED: Candidate URL extracted by discovery engine.
NAVIGATING: Playwright page load in progress.
REAL_PRODUCT: Page verified as an authentic, active single-product detail page.
NOT_PRODUCT: Verified as a collection index, blog post, cart, checkout, or policy page.
BLOCKED: Cloudflare challenge, bot verification interstitial, 403 Forbidden, or geo-block.
ERROR: 404 Not Found, 500 Server Error, DNS resolution failure, or navigation timeout.
UNKNOWN: Unclassified page state due to evaluation failure.
Transitions
DISCOVERED -> NAVIGATING
NAVIGATING -> REAL_PRODUCT | NOT_PRODUCT | BLOCKED | ERROR | UNKNOWN
Rules & Invariants
FORBIDDEN TRANSITION: BLOCKED -> REAL_PRODUCT
FORBIDDEN TRANSITION: NOT_PRODUCT -> REAL_PRODUCT
FORBIDDEN TRANSITION: UNKNOWN -> REAL_PRODUCT (Requires positive structural verification)
SYSTEM INVARIANT: Scan engines (Variant, BIS, CRO) MUST ONLY execute when PageState == REAL_PRODUCT.
2. VARIANT STATE MACHINE (VariantState)
States
UNKNOWN: Variant availability cannot be conclusively determined.
IN_STOCK: Variant is available for purchase (ATC button enabled, stock confirmed).
OUT_OF_STOCK: Variant is confirmed out of stock (disabled pill/option, explicit sold-out indicator).
AMBIGUOUS: Element disabled due to pre-selection requirement, loading state, or non-variant UI.
Transitions
UNKNOWN -> IN_STOCK | OUT_OF_STOCK | AMBIGUOUS
AMBIGUOUS -> IN_STOCK | OUT_OF_STOCK (After option selection click interaction)
Rules & Invariants
AMBIGUOUS MUST NEVER transition directly to OUT_OF_STOCK without click verification.
UNKNOWN MUST NEVER trigger a REVENUE_LEAK commercial opportunity.
3. BACK-IN-STOCK STATE MACHINE (BISState)
States
PRESENT: Active Back-In-Stock notification modal, form, or trigger button detected on OOS page.
ABSENT: BIS mechanism verified absent on confirmed OOS page state.
UNKNOWN: Page state not OOS, or BIS detection inconclusive.
Transitions
UNKNOWN -> PRESENT | ABSENT (Valid ONLY when VariantState == OUT_OF_STOCK)
Rules & Invariants
BIS evaluation is INVALID if VariantState != OUT_OF_STOCK.
ABSENT + VariantState.OUT_OF_STOCK -> Triggers REVENUE_LEAK candidate.
UNKNOWN -> Suppresses REVENUE_LEAK candidate.
4. REVIEW STATE MACHINE (ReviewState)
States
PRESENT: Customer review widget, rating stars, or JSON-LD AggregateRating verified.
ABSENT: Social proof verified absent via multi-layer DOM + JSON-LD + text pattern audit.
UNKNOWN: Hardcoded selectors absent, but broader absence cannot be conclusively proven.
Transitions
UNKNOWN -> PRESENT | ABSENT
Rules & Invariants
UNKNOWN MUST NOT transition to ABSENT based solely on CSS selector failure.
ABSENT -> Triggers MISSING_SOCIAL_PROOF candidate.
UNKNOWN -> 0 commercial opportunities.
5. UPSELL STATE MACHINE (UpsellState)
States
PRESENT: Product recommendations, cross-sell modules, or cart drawer upsells verified.
ABSENT: Upsell infrastructure verified absent via multi-surface inspection.
UNKNOWN: Recommendation selectors absent; behavioral cart state unverified.
Transitions
UNKNOWN -> PRESENT | ABSENT
Rules & Invariants
Default state for non-behavioral inspection is UNKNOWN.
UNKNOWN MUST NOT generate a Class A commercial lead.
6. STICKY ATC STATE MACHINE (StickyATCState)
States
PRESENT: Persistent purchase CTA verified in mobile viewport fold during page scroll.
ABSENT: Page scrollHeight >= 1200px and no sticky CTA accessible in lower fold.
UNKNOWN: Page scrollHeight < 1200px or mobile viewport inspection incomplete.
Transitions
UNKNOWN -> PRESENT | ABSENT (Requires mobile context scroll evaluation)
Rules & Invariants
ABSENT + scrollHeight >= 1200 -> Triggers MISSING_STICKY_ATC candidate.
UNKNOWN -> Suppresses opportunity.
7. EVIDENCE STATE MACHINE (EvidenceState)
States
CAPTURED: Screenshot PNG bytes collected from Playwright page context.
VALID: PNG stream verified (non-corrupt, >=1024x600, non-blank canvas).
INVALID: PNG stream corrupt, sub-minimum dimensions, or blank canvas.
RELEVANT: Screenshot visually matches the exact product & finding state.
IRRELEVANT: Screenshot depicts a different PDP, Cloudflare wall, or stale state.
MISSING: No screenshot captured.
Transitions
CAPTURED -> VALID | INVALID
VALID -> RELEVANT | IRRELEVANT
Rules & Invariants
Lead export REQUIRES EvidenceState == RELEVANT.
IRRELEVANT or INVALID evidence demotes lead to Class C — NOT SELLABLE.
8. COMMERCIAL FINDING STATE MACHINE (FindingState)
States
CANDIDATE: Finding generated by primary opportunity engine.
CONFIRMED: Finding validated against page state, evidence relevance, and confidence gate.
REJECTED: Finding failed quality gate (unverified page state, false positive pattern).
UNKNOWN: Finding certainty inconclusive.
Transitions
CANDIDATE -> CONFIRMED | REJECTED | UNKNOWN
Rules & Invariants
FORBIDDEN TRANSITION: UNKNOWN -> CONFIRMED without new positive evidence.
FORBIDDEN TRANSITION: UNKNOWN -> SELLABLE (Class A).
ONLY CONFIRMED findings are eligible for commercial lead export.

SYSTEM INVARIANTS — REVENUELEAKSCANNER V2

CORE INVARIANTS MATRIX
INV-001: A blocked, interstitial, or non-product page (PageState != REAL_PRODUCT) MUST NEVER produce a commercial opportunity or lead.

INV-012: Downstream engines MUST reject invalid or unverified upstream contracts instead of silently accepting contaminated inputs.

When in doubt, evaluate to UNKNOWN and issue NO COMMERCIAL CLAIM.
The system must NEVER convert ambiguity, timeouts, or detection failures into commercial opportunities.

DOCUMENT 7: ANTI-REGRESSION PRINCIPLES
ANTI-REGRESSION PRINCIPLES — REVENUELEAKSCANNER V2
These 15 principles are derived directly from forensic code audits of RevenueLeakScanner_V2. They represent non-negotiable engineering rules.

Selector failure DOES NOT equal feature absence. Never infer a commercial problem from a missing CSS selector unless positive proof of absence is established.
Never execute commercial detection before page-type validation. Every candidate URL must be positively verified as a REAL_PRODUCT page before running scanner engines.
UNKNOWN state MUST NEVER generate a commercial opportunity. Ambiguous detections must default to zero opportunities.
Never reuse a single session-level screenshot across multiple PDP findings. Every finding must anchor its own verified screenshot captured during that specific PDP inspection.
PNG stream validity DOES NOT imply claim validity. A valid PNG file of a Cloudflare wall or wrong page is not valid visual evidence for a CRO finding.
Never present benchmark fallbacks as store-specific facts. Hardcoded parameters (50k traffic, $65 AOV, 2% CR) must be explicitly disclosed as "Benchmark Scenario Estimates".
Scan coverage completeness DOES NOT determine commercial lead class. Class A status requires evidence quality and confirmed opportunity strength, not just 3 inspected PDPs.
Never pass unvalidated inputs across engine contracts. Upstream components must guarantee data contracts before downstream consumption.
Never rely on narrow CSS selector matching for semantic states. Use multi-layer verification (DOM, JSON-LD, ARIA, computed CSS, scroll behavior).
Never count the same entity multiple times due to URL variations. Deduplication must occur at the true domain/SKU identity level.
enrichment_status = "SUCCESS" REQUIRES actual populated contact data. A function finishing without throwing an exception is not success.
Never patch architectural defects with more CSS selectors. If the detection principle is flawed, fix the state model and behavioral verification architecture, not the selector array.
Define strict system contracts BEFORE writing implementation code. Code must fulfill explicit contract specifications.
Passing unit tests DOES NOT prove commercial correctness. Tests prove code execution; commercial validity requires forensic proof against real store data.
Lead quantity IS NOT success if precision is low. A smaller set of verified, evidence-backed leads is infinitely more valuable than hundreds of unverified, false-positive leads.
